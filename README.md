# Realm Wardens — generated asset snapshot

AI-generated game assets for the *Realm Wardens* prompt specification (90 3D assets + 19 pieces of 2D art),
produced with **TapTap Maker** (`generate_image` / `create_3d_asset`) on 2026-11-24.

This snapshot contains **only** the assets generated in that run — no other project files.

## Pipeline

1. **Concept image** — `generate_image` / `batch_generate_images`, 1:1 1024×1024, prompt + shared style block.
2. **3D** — `create_3d_asset` with `generation_strategy=direct`, concept image as the front view
   (`image_to_model`). Quality tier per group: bosses and heavy characters `high_quality`, ordinary units
   `balanced`, map props `fast`. Face limit: characters/towers 6000, bosses 15000, props 1500.
3. **2D art** — `generate_image` at the sizes listed above.

Reproduce or extend with:

```bash
python3 tools/realm_wardens_manifest.py            # rebuild manifest.json
python3 tools/realm_wardens_gen.py concepts        # concept images
python3 tools/realm_wardens_gen.py models --parallel 4
python3 tools/realm_wardens_gen.py art
python3 tools/realm_wardens_gen.py status
```

`docs/realm-wardens/state.json` makes the driver resumable: delete an entry to regenerate that asset.

## Known deviations from the original spec

The source spec asked for a single GLB per asset with vertex colors, code-rotated sub-objects
(`ArmR__archer`, `Turret`, …) and a hard triangle budget. What Maker delivers differs:

- **Format**: one UrhoX package per asset (`UMD2 .mdl` + PBR materials + 1K textures + prefab), not a GLB.
- **Surfaces**: textured PBR materials rather than baked vertex colors.
- **Rigging**: assets are fused single meshes. No skeletal rig was applied, and the animated part keys are
  recorded in `manifest.json` but **not** split into separate nodes. A Blender pass (or
  `create_3d_asset` `post_process: retopology / rig`) is needed for the original loader contract.
- **Budget**: `face_limit` was requested per asset; the service trims by quality tier but per-asset triangle
  counts were not verified. Total is ~308 MB (122 MB meshes + 114 MB textures).
- **Axes / origin**: poses come from image-to-3D; facing and pivot were not normalized to y=0 / +Z.
